# Домен для Fodder VPN (устойчивый вход в РФ)

Цель: увести точку входа (страница `/connect`, панель, sub-страница) с ненадёжного
`nip.io` на **свой домен**, чтобы её нельзя было заблокировать «оптом» и чтобы можно
было быстро увести на новый IP при блокировке.

## ⚠️ Главное про Cloudflare в РФ (прочитай первым)

С июня 2025 российские провайдеры **троттлят трафик к сети Cloudflare** (грузится
~первые 16 КБ страницы — сайт фактически не открывается). Поэтому:

- **НЕ включай проксирование Cloudflare (оранжевое облако)** для этих доменов — в РФ
  это сделает вход НЕдоступным.
- Cloudflare можно использовать **только как DNS-хостинг с проксированием ВЫКЛ
  (серое облако)** — тогда трафик идёт напрямую на твой VPS, мимо Cloudflare-edge, и
  троттлинг его не касается. Либо используй DNS любого регистратора — без разницы.

То же касается выбора VPS: Hetzner/DigitalOcean/OVH тоже под троттлингом — предпочитай
провайдеров, которые в РФ ещё нормально ходят, и держи запасной.

## Шаг 1. Купить домен (~$1–10/год)

Полностью бесплатного надёжного варианта нет (бесплатные поддомены блокируются оптом,
как nip.io). Дёшево и надёжно:

- **Cloudflare Registrar** — по себестоимости, без наценки (напр. `.com` ~$10/год).
- **Porkbun / Namecheap** — промо на первый год от ~$1 (`.xyz`, `.click`, `.top`).

Выбери короткий нейтральный домен (не содержащий «vpn»/«proxy» в имени — меньше
поводов для авто-блокировки). Пример дальше: `example.com`.

## Шаг 2. DNS — три A-записи на IP твоего VPS (проксирование ВЫКЛ)

| Поддомен              | Тип | Значение (IP VPS) | Proxy      |
|-----------------------|-----|-------------------|------------|
| `vpn.example.com`     | A   | 77.67.89.164     | **OFF** (DNS only) |
| `panel.example.com`   | A   | 77.67.89.164     | **OFF** |
| `sub.example.com`     | A   | 77.67.89.164     | **OFF** |

- `vpn.` — API vpn_wizard: отдаёт `/connect`, `/miniapp`, AWG-эндпоинты.
- `panel.` — админка Remnawave.
- `sub.` — клиентская страница подписки Remnawave.

(Если панель/ноды на разных серверах — направь `panel`/`sub` на IP панельного VPS.)

## Шаг 3. Прописать домены в Caddy (TLS выпустится сам)

На VPS с vpn_wizard:
```bash
# vpn-wizard уже за Caddy (deploy/vpn-wizard.Caddyfile использует {$VPNW_DOMAIN})
export VPNW_DOMAIN=vpn.example.com   # в окружении сервиса vpn-wizard
sudo systemctl restart vpn-wizard caddy
```
На панельном VPS — `deploy/remnawave/Caddyfile.example` уже с двумя блоками; заменить
`panel.example.com` / `sub.example.com` на свои, затем `sudo systemctl reload caddy`.

Caddy сам получит Let's Encrypt-сертификаты (A-записи должны уже указывать на VPS).

## Шаг 4. Обновить URL в конфигах на новый домен

- Панель `.env`: `SUB_PUBLIC_DOMAIN=sub.example.com`, `PANEL_DOMAIN=panel.example.com`.
- Бот Bedolaga `.env`: `VPNW_AWG_PUBLIC_URL=https://vpn.example.com`,
  `FODDERS_VPN1_MINIAPP_URL=https://vpn.example.com/miniapp`.
- vpn_wizard `.env`: `VPNW_REMNAWAVE_API_URL=https://panel.example.com` (или внутренний),
  `VPNW_MINIAPP_URL=https://vpn.example.com/miniapp`.
- BotFather → `/setdomain` для Login Widget/Mini App = `vpn.example.com`.
- Ссылка-вход для людей: `https://vpn.example.com/connect/?sub=<их_ссылка>`.

## Шаг 5. Живучесть (сделать сразу)

- **Запасной домен** у другого регистратора, DNS готов — чтобы за минуты переключить,
  если основной заблокируют.
- **Ротация IP:** если IP заблокируют, подними новый VPS, поменяй A-записи (DNS-only —
  меняется быстро), Caddy перевыпустит серт. Пользователи ничего не делают.
- **TTL** DNS-записей поставь низким (напр. 300 с), чтобы переключения применялись быстро.
- nip.io оставь как аварийный запасной вход, но не как основной.
