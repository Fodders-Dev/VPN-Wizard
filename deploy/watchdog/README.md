# Оповещения: сторож блокировок + баннер на сайте

Два инструмента, закрывающие разные случаи. Внезапный блок IP убивает и сайт —
в этот момент до людей достаёт только Telegram/SMS, а тебя будит сторож.
Плановую смену адреса и «перевыпустите профиль» объявляет баннер на сайте.

## 1. Сторож `fodder-ru-watchdog` (алерт тебе в Telegram)

Раз в 10 минут спрашивает check-host.net, видны ли из России NL
`77.67.89.164:443` и FI `193.222.97.50:22` (ноды ru1/ru2/ru3; контроль —
il2/ro1). Для FI проверяется TCP/22, а не рабочий UDP-порт: check-host умеет
только TCP, а блокировки РКН на этих хостерах приходят на весь IP сразу. Три вердикта: `ok`, `blocked` (ru не видят, мир видит — похоже на
РКН), `down` (не видит никто — лежит сервер). Пишет владельцу из
`VPNW_OWNER_IDS` через бота (`VPNW_TELEGRAM_AUTH_TOKEN`) **только при смене
состояния**, напоминает раз в 6 часов, шлёт отбой при восстановлении.

Установка (на rodnya, из свежего чекаута):

```bash
install -m 755 /opt/vpn-wizard/app/deploy/watchdog/fodder-ru-watchdog /usr/local/bin/
cp /opt/vpn-wizard/app/deploy/watchdog/fodder-ru-watchdog.{service,timer} /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now fodder-ru-watchdog.timer
```

Заодно снимает **ресурсы** каждой коробки (панель локально, экзиты по SSH из
`VPNW_AWG_SERVERS`) и предупреждает ЗАРАНЕЕ: загрузка > 4 на ядро, свободной
памяти < 12%, свободного диска < 10%, TCP-буферы ядра > 85% лимита. Последний
порог — про аварию 23.08.2026: сервер был доступен, HTTP отвечал, а TLS вставал,
потому что `tcp_mem` упёрся в потолок (см. [[rodnya-tcp-mem-outage]]).

### Молчащие интерфейсы

Третья проверка отвечает на вопрос, который не задаёт ни одна из первых двух:
**доходят ли до сервера живые люди**. Интерфейс, у которого есть профили, но нет
ни одного хендшейка дольше суток, — это молча отрезанная аудитория.

Так вскрылась история с `awg1`: 22.08.2026 миграция переписала 61 профиль на
новый адрес, но файлы людям на руки никто не раздал, и шесть суток шестьдесят
один человек сидел без VPN. Сервер всё это время был доступен, по ресурсам
свободен, порт слушал — и ни один алерт не сработал, потому что мерили не то.

Порог — `VPNW_WATCHDOG_SILENT_HOURS` (по умолчанию 24). Интерфейсы меньше чем с
пятью профилями игнорируются: это стенды и личные туннели на чужих коробках.
Свежеподнятый интерфейс тоже не обвиняется — перезапуск обнуляет все хендшейки,
поэтому возраст хендшейка считается только если интерфейс живёт дольше окна.

Заодно там же проверяется, что на интерфейсе стоит правило `TCPMSS --set-mss`
(без него крупные TCP-пакеты молча гибнут — авария 28.08.2026, см.
[[awg-mss-blackhole]]) и что тулза умеет `syncconf` (без него выдача одного
профиля рвёт сессии всем).

Посмотреть состояние интерфейсов прямо сейчас, ничего не отправляя:
`set -a; . /etc/vpn-wizard.env; set +a; /usr/local/bin/fodder-ru-watchdog --interfaces`

Проверка доставки: `systemd-run --wait -p EnvironmentFile=/etc/vpn-wizard.env /usr/local/bin/fodder-ru-watchdog --test`
(придёт пробное сообщение). Текущие цифры без алертов:
`set -a; . /etc/vpn-wizard.env; set +a; /usr/local/bin/fodder-ru-watchdog --capacity`.
Состояние: `/var/lib/fodder-ru-watchdog/state.json`, логи: `journalctl -u fodder-ru-watchdog`.

При смене IP поправь адреса в `TARGETS` внутри скрипта и переустанови его.

## 1b. Ежедневная сводка `fodder-daily-digest`

Раз в сутки (21:07 МСК) присылает в Telegram: сколько профилей выдано, у скольких
**заработал хотя бы раз**, сколько пользовались за сутки, разбивку по странам и
остаток общего кода.

Ключевая метрика — «заработал хотя бы раз» (`first_handshake_at`). Обычный
«последний хендшейк» для этого не годится: выдача любого профиля перезапускает
`awg-quick`, после чего WireGuard рапортует «never» сразу для всех пиров, и
сводка показывала бы горстку живых вместо реальной картины.

```bash
install -m 755 /opt/vpn-wizard/app/deploy/watchdog/fodder-daily-digest /usr/local/bin/
cp /opt/vpn-wizard/app/deploy/watchdog/fodder-daily-digest.{service,timer} /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now fodder-daily-digest.timer
```

Посмотреть цифры прямо сейчас, ничего не отправляя:
`set -a; . /etc/vpn-wizard.env; set +a; /usr/local/bin/fodder-daily-digest --print`

## 2. Баннер на сайте (`web/connect/status.json`)

`atlas.js` на каждой странице (`/connect/*`, `/portal/`) читает
`/connect/status.json` и, если `notice` непустой, показывает жёлтый баннер
сверху. Правится **прямо на GitHub в браузере** (кнопка ✏️ на файле) — коммит
в main доезжает до сервера автодеплоем за ~минуту.

```json
{"notice": "1 сентября сменится адрес сервера — после этого зайдите по новой ссылке и скачайте профиль заново.",
 "until": 0,
 "servers": {"nl": "", "fi": "Финляндия сегодня ночью недоступна — чиним."}}
```

`notice` видят все; `servers.<id>` — только люди этого сервера (страница
подключения знает свой `?server=`). `until` — unix-время, после которого
баннер сам исчезает (0 = показывать пока не сотрёшь). Выключить: вернуть
пустые строки.

Предпросмотр без правки файла: открой любую страницу с
`#status-preview=Текст%20баннера`.

## 3. Каналы доставки, когда IP уже мёртв

1. Пост в канал **@fodders_dev** (подписчики бесплатного доступа стягиваются
   туда онбордингом) — дойдёт до всех, у кого Telegram жив.
2. Рассылка по юзерам бота — админка Бедолаги в @foddervpnbot.
3. SMS/звонок тем, кто без Telegram, — готовый текст с новой ссылкой
   (шаблон — в RUNBOOK-managed).

Структурное лекарство от всего раздела — свой домен (`deploy/DOMAIN-SETUP.md`):
ссылки переживают смену IP, а если выпускать AWG-конфиги с
`Endpoint = <домен>`, то после смены IP профили продолжают работать сами,
без перевыдачи — меняется только A-запись.
